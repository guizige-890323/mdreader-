## 1. 阶段总览

项目采用**「已完成基线 + 闸门式增量」**模型：v1.0–v1.7 的功能开发已完成并验证，后续按 CR（变更单）推进，每个 CR 严格走四步闸门。本计划把"待确认存量"与"后续增量"统一排期。

### 1.1 闸门流程（每个阶段强制）

```
① 输出变更单（改什么/为什么/影响面/风险/验证口径）
② 只做网页版（src/* → dist/MDReader.html）+ 专项测试 + 关键回归 + 截图
③ 停下等产品负责人（桂子哥）确认 ← 闸门
④ 确认后：四端同步（dist-intl/desktop/ios/mdlens）+ 全量回归 + 重打五产物 + CHANGELOG
```

**铁律**：③ 未确认前不得触碰 dist-intl / desktop / ios / mdlens / 打包脚本；历史断言零删除零放宽；断言与新契约冲突时修实现。

## 4. 验收与交付物管理规范

1. **每阶段出口三件套**：变更单（含确认记录）+ 回归日志（`_shots/reg*-summary.txt`）+ 产物哈希清单。
2. **截图归档**：关键交互态截图存 `_shots/`，命名 `cr<NN>-<态>-<主题>.png`，目视复核记录写日志。
3. **文档同步**：功能行为变化 → 更新 01/03 对应章节；架构变化 → 更新 02 + ADR；排期变化 → 更新本文档并提升版本号。
4. **记忆沉淀**：每阶段完成追加 `.workbuddy/memory/YYYY-MM-DD.md`（append-only），跨会话可追溯。
5. **Definition of Done**：代码+断言+截图+日志+确认+四端同步+产物+文档，八项齐备才算完成；缺一不得宣布交付。
