## 二、逐项详解
### 01 · Markdown 复制即创建

| | |
|---|---|
| 英文名 | CLIPBOARD → DOC |
| 级别 | P0 · 核心差异化 |
| 入口 | 顶栏「创建 MD」按钮悬停（`Ctrl+N`） |

**一句话**：AI 吐出的那段 Markdown，悬停一下就变成能读的文档。

**详细说明**
复制 AI 回复里的 Markdown，鼠标移到顶栏「创建 MD」上，面板自动检测剪贴板内容并识别 Markdown 特征（标题、列表、代码块、表格、链接），点「⚡ 粘贴并创建」立刻渲染成排版完整的页面。

三条通道按环境自动降级，不会卡死：
1. 桌面版直接读系统剪贴板；
2. 浏览器允许时走 `navigator.clipboard`；
3. 本地 `file://` 下浏览器一律禁读，面板直接把光标放进备用输入框，提示「按 `Ctrl+V` 立刻创建」——只需一次按键，不要求用户去改浏览器设置。

创建后立即渲染，`Ctrl+S` 另存为 `.md`，从「AI 输出」到「磁盘上的文档」是一条通路，中间不落地任何临时文件。

**使用场景**：跟 AI 聊完一段方案 / 一份排查步骤，不想再开编辑器粘贴保存——复制、悬停、点击，三步成文。

**对照**：`Ctrl+V` 进编辑器 → 手动存盘 → 再拖进阅读器（三步变一步）。

**标签**：剪贴板检测 · 一键成文 · 三通道降级

### 02 · 表格，秒变六种图表

| | |
|---|---|
| 英文名 | SIX CHART TYPES |
| 级别 | P0 · 核心差异化 |
| 入口 | 表格右上角图表按钮条 / 设置内「默认图表风格」 |

**一句话**：表格选两列就出图，六种图型随数据形态自动选。

**详细说明**
表格本身已经不只是静态表：斑马纹、悬停高亮、表头固定、**点表头排序**、数值列自动右对齐、复制为 CSV / TSV。在此之上，选中两列即可生成图表，六种型别：

| 图型 | 适合的数据 |
|---|---|
| 自动 | 按数据形态替你选（默认） |
| 柱状 | 分项对比、离散类别 |
| 折线 | 连续趋势、时间序列 |
| 趋势 | 强调方向与拐点 |
| 环形（圆角） | 构成占比，中心留空放总计 |
| 南丁格尔玫瑰 | 多项占比、半径表达量级 |

**一个容易被忽略但很关键的点**：环形图的扇区角度是按分项**百分比精确累计划分**（33.0% → 118.8°，0.3% → 1.08°），不是等角均分。图例百分比与扇区角度一一对应、可以拿量角器验算——数据汇报里这一点经得起追问。

图表还带「工具条常驻 + 表格与图联动」：表头排序后图立即重绘；同一份数据切换图型不丢当前配色风格。

**标签**：6 型图表 · 智能选型 · 精确累计划分 · CSV / TSV

### 03 · 双引擎流程图

| | |
|---|---|
| 英文名 | DUAL-ENGINE FLOW |
| 级别 | P0 · 核心差异化 |
| 入口 | ` ```mermaid ` 代码块 / ` ```flow ` 文本流 / 正文里的 Unicode 框线图 |

**一句话**：Mermaid 与字符画两条入口，都落到同一条可拖拽编辑的矢量链路。

**详细说明**
三条输入路径，一个输出：

1. **Mermaid 原生**：`flowchart` / `sequenceDiagram` / `gantt` 直接渲染，主题跟随明暗。
2. **文本即图形**：用 `→` `⇒` 箭头或 `[节点]` 写法的 ` ```flow ` 代码块，支持 ①②③ 符号占位与回环，交给 MD FLOW 出图。
3. **字符架构图识别**：用 `┌─┐│└┘` 等 Unicode 框线画的功能架构图（直接粘在正文或放进代码块都行），**不依赖 AI、不联网**，由纯 JS 算法按 UAX #11 显示列宽展开字符网格、聚类框行带与竖线槽、提取框内文字与层间连线证据，还原成 `{nodes, edges}` 语义图再交给 MD FLOW 出图。中英混排、顶边缺失、边界列漂移、扇出 / 汇合、左侧外部输入标注都能容错。

**两条正交轴**，也是这块最容易讲错的地方：

- **结构**（怎么排）：自动 / 多彩流水 / 思维导图 / 组织结构图 / 时间图
- **风格**（什么色）：经典 / 极简 / 商务 / 活力 / 暗夜

5 × 5 = 25 种外观，互不干扰。结构下沉到**每张流程图右上角**单独选，按源码 hash 记忆；改结构、换主题、重开文档都不丢。

**编辑能力**：工具条 ✎ 编辑——拖拽节点（连线实时跟随）、双击改文字、8 色强调色、复位位置、新增节点 / 连线 / 删除节点、撤销、重置。下层几何与上层位置**双层状态分开记忆**。

**导出即最后编辑状态**：下载 SVG / 复制源码 / 导出 HTML / Word / 打印 PDF 全部以你拖动后的位置为准，导出只剥离编辑器 UI，**不重绘回自动布局**。

**标签**：Mermaid + 文本流 + ASCII 识别 · 5 结构 × 5 风格 · 导出即编辑态

### 04 · 一套令牌，五处同频

| | |
|---|---|
| 英文名 | ONE PALETTE, EVERYWHERE |
| 级别 | P0 · 核心差异化 |
| 入口 | 设置 → 文档风格（黑白 / 蓝 / 红 / 粉） |

**一句话**：四套文档风格一次改全局：分段背景、图表、流程图、代码高亮同频。

**详细说明**
多数工具的「配色」只管正文强调色，图表和流程图还是自己那套色板，一份文档里三种蓝、两种红。MD Reader 的做法是**一个风格令牌驱动五处渲染**：

| 被驱动的东西 | 效果 |
|---|---|
| 分段背景与卡片徽章 | 按 `##` 分节时每节底色与编号徽章跟着走 |
| 图表色板 | 柱状 / 折线 / 趋势 / 环形 / 玫瑰同步换装 |
| 流程图强调色 | 节点描边、主线、编号徽章同色系 |
| 代码关键字高亮 | 关键字 / 字符串 / 注释使用同一色相家族 |
| 表格配色 | 表头、斑马纹、选中态一致 |

四套风格在**浅色 / 深色 / 护眼**三种主题下各自派生可读变体——不是把浅色方案直接铺到深色底上，而是每个主题有独立的对比度校准，实测在深色与护眼下都不出现「深底压深字」。

导出 HTML / SVG 时用 `<html style>` 固化 23 个风格变量（并支持 `var(--x, rgb(...))` 嵌套兜底的循环展开），所以离线文件与屏幕上看到的一模一样，不会导出后发现颜色全丢。

**使用场景**：技术汇报走「蓝」、政企材料走「红」、给孩子讲课走「粉」、论文与打印稿走「黑白」。

**标签**：一套令牌五处同频 · 三主题派生 · 导出不丢色

### 05 · 知识库原生双链

| | |
|---|---|
| 英文名 | NATIVE WIKI LINKS |
| 级别 | P0 · 核心差异化 |
| 入口 | 直接打开 Obsidian 库（拖入文件夹） |

**一句话**：Obsidian 的双链、嵌入、Callout、frontmatter 开箱即渲染。

**详细说明**
上千篇笔记的库，拖进窗口就能读，不需要先「导入」、不需要装插件、不需要先把笔记转成别的格式：

| 语法 | 渲染结果 |
|---|---|
| `[[双链]]` | 可点击跳转（同库内解析） |
| `![[图片]]` | 内嵌显示 |
| `[!note]` / `[!warning]` 等 Callout | 带图标与配色的提示块 |
| YAML frontmatter | 渲染成属性表，不显示成一段难看的分隔线 |
| `#标签` | 高亮渲染 |
| MOC 索引页 | 大纲与锚点跳转照常可用 |

侧栏文件树按文件夹递归展开、懒加载，1000+ 文件整库浏览不卡；UTF-8 / GB18030 编码自动识别，中文老文档不会出乱码。

**使用场景**：自己的第二大脑不想为「看一眼」而启动整套 Obsidian；或者要把内网笔记给同事看，又不能上传到任何在线服务。

**标签**：双链 · 嵌入 · Callout · frontmatter · 整库懒加载

### 06 · 导出，仍是活页面

| | |
|---|---|
| 英文名 | EXPORT THAT LIVES |
| 级别 | P0 · 核心差异化 |
| 入口 | 导出菜单 / 打印 |

**一句话**：导出的 HTML 仍可点、可切图型、可复制 CSV；Word / PDF 保真。

**详细说明**
| 目标 | 保留什么 |
|---|---|
| 独立 HTML | 样式与图片**内嵌**，单文件可分发；图表可切型、CSV 可复制、表格可排序——是活页面，不是截图 |
| Word (.docx) | 排版保真，流程图与图表以矢量 / 图片形式随文档带走 |
| 打印 / PDF | 通过浏览器打印管线，`.mf-tools` / `.ad-src` / `.ad-warn` 等编辑态控件自动隐藏 |
| SVG | 流程图与图表单独下载，`inlineVars()` 循环展开 `var()`，不含 CSS 变量残留 |
| Markdown 源码 | 当前文档原文原样带走 |

统一口径：**导出 = 当前 DOM 的克隆**，所以导出内容永远等于你「最后编辑的状态」——拖过节点、切过图型、换过配色，导出的就是这一个样子。

**标签**：HTML / Word / PDF / SVG / 源码 · 导出即编辑态 · 单文件可分发

### 07 · MCP 连接器

| | |
|---|---|
| 英文名 | MCP READY |
| 级别 | P0 · 核心差异化 |
| 入口 | `mdlens`（CLI / HTTP / MCP Server） |

**一句话**：AI 工具通过 MCP / CLI / HTTP 直接把 Markdown 渲染成页面。

**详细说明**
`mdlens` 是配套的渲染服务，三种接入方式共用一套引擎：

| 接入 | 命令行 / 协议 | 谁在用 |
|---|---|---|
| CLI | `mdlens render <file.md>` | 脚本、批处理、CI |
| HTTP | 本地端口，POST Markdown → 返回 HTML / 图片 | 自建 Web 工具、编辑器插件 |
| MCP | 标准 MCP Server | Claude / Codex / WorkBuddy 等支持 MCP 的 AI 工具 |

价值在于闭环：AI 产出 Markdown → MCP 工具直接渲染 → 用户在漂亮页面里校对，而不是在聊天窗口里读一堆竖线和反引号。整个链路可以完全离线（引擎内联，不调用任何云端渲染服务）。

**标签**：CLI / HTTP / MCP · 离线引擎 · AI 工具直连

### 08 · 大纲与按块编辑

| | |
|---|---|
| 英文名 | OUTLINE & BLOCK EDIT |
| 级别 | P1 · 体验领先 |
| 入口 | 侧栏大纲 / `Ctrl+E` 编辑源码 / `Ctrl+S` 保存 |

**一句话**：按块改，不再把整篇塞进编辑器；保存后换行与 frontmatter 分毫不差。

**详细说明**
侧栏大纲按标题层级生成，点击即跳锚点，长文定位不用滚。卡片排版下大纲与锚点照常可用（标题 `id` 原样保留），不会因为换了皮肤就失灵。

编辑采用**按块编辑**：段落、标题、列表、表格、代码块、流程图源码各自切成独立小块，逐块修改，只重渲染受影响的那块。相比把几万字一次性塞进一个 textarea，好处是滚动不乱序、光标不跳、大表格编辑不卡顿。

保存（`Ctrl+S`）写回原文件时，换行符（CRLF / LF）与 YAML frontmatter 原样保留，不会因为「保存一次」就把整个仓库的 diff 炸开——这一点对 Git 管理笔记库的人是刚需。

**标签**：大纲跳转 · 块级编辑 · 换行保真 · frontmatter 保真

### 10 · 最近，重读磁盘

| | |
|---|---|
| 英文名 | RECENT, RE-READ FROM DISK |
| 级别 | P1 · 体验领先 |
| 入口 | 顶栏「最近打开」/ `Ctrl+R` |

**一句话**：点历史记录是**重读磁盘原文**，不是打开一张旧快照。

**详细说明**
最多保留 30 条记录。点历史记录时的行为是——按绝对路径**重新读磁盘上的文件**，所以你昨天用别的工具改过的内容，今天点进来就是最新的。文件被移走或改名时，自动退回正文缓存，不会只给一个报错弹窗。

同时记住上次的阅读位置，接力阅读零成本；配合 `F5` 强制重读当前文件，边改边看不用重新打开。

**对照**：多数阅读器缓存的是打开时的内容快照，改完文件再点历史记录还是老样子。

**标签**：30 条 · 按路径重读 · 位置记忆 · 丢失退缓存

### 12 · 专注模式

| | |
|---|---|
| 英文名 | FOCUS MODE |
| 级别 | P1 · 体验领先 |
| 入口 | 顶栏专注按钮 / `Ctrl+O`，`Esc` 退出 |

**一句话**：隐去侧栏与工具条，只留正文、进度与一行快捷键。

**详细说明**
一键收起文件树、侧栏、工具条，视口里只剩正文与阅读进度条；渲染相关的快捷菜单仍然保留（表格排序、图表切换、流程图编辑都还能用），所以「专注」不等于「功能被砍掉」。右侧显示当前滚动百分比，读完一篇长文不需要靠感觉判断还剩多少。

`Ctrl+O` 进入，`Esc` 或点角落按钮退出，退出后侧栏宽度、选中文件、滚动位置全部原样恢复。

**使用场景**：读运维手册、看长报告、给别人讲文档时投屏——不希望在画面里露出自己的文件树。

**对照**：多数阅读器只能靠手动折叠面板，且折叠后功能一起消失。

**标签**：零干扰 · 保留渲染菜单 · 一键还原

### 13 · 云晰柔光

| | |
|---|---|
| 英文名 | SOFT LIGHT |
| 级别 | P1 · 体验领先（原创） |
| 入口 | 设置 → 云晰柔光开关 / 阅读区柔光弹层 |

**一句话**：柔光铺满全应用，色阶连续无断层，不是简单反色。

**详细说明**
常见的「夜间模式」只是把背景调暗、文字调亮，结果顶栏还是刺眼的白、侧栏还是硬边阴影，界面被切成几块。云晰柔光做的是**全链路柔化**：

- 覆盖范围：顶栏 / 侧栏 / 标签栏 / 阅读区 / 弹层，一处不落
- 实现方式：降低局部对比与边缘锐度，同时保持文字对比度在可读区间（不是无脑降低亮度）
- 色阶连续：从背景到卡片到浮层是同一条渐变色阶，不出现「一块块贴上去」的断层
- 可叠加：与浅色 / 深色 / 护眼三主题都能叠加，参数会记住

**标签**：全链路柔化 · 色阶连续 · 可叠加三主题

### 15 · 国际化版本

| | |
|---|---|
| 英文名 | I18N |
| 级别 | P2 · 交付完备 |
| 入口 | 设置 → 语言 / Language |

**一句话**：简体中文 / English / 跟随系统，正文永不参与翻译。

**详细说明**
实现方式值得说明一句：源语言就是简体中文（`zh-CN` 字典为空，直接显示原文），其余语言以「中文原文 → 译文」映射，运行时按 **key 长度降序**替换（长句优先，避免短词先把长句吃掉）。未收录的词条保持中文原文，便于逐轮补齐——所以英文界面不会出现大片 `undefined` 或机器占位符。

## 四、文案使用约定

三处产出物共用本文，但**裁切长度不同**，各取不同字段：

| 产出物 | 标题 | 副标题 | 正文 | 标签 |
|---|---|---|---|---|
| 功能展示页卡片 | 15 字内 | 英文名 | 详细信息的第一句（≤ 60 字） | 2–3 个 |
| 欢迎屏滚动展板 | 15 字内 | 无 | 压缩到 ≤ 46 字（一行读完） | 无 |
| 产品介绍 GIF | 15 字内 | 英文名 | ≤ 24 字 | 无 |

修改文案时**先改本文**，再重新构建三处，否则会出现「页面说的和 GIF 说的不一样」。
