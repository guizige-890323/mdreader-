## 二、渠道矩阵：先想清楚每个平台"要它干什么"

很多人的推广失败，是因为把同一段文案贴到所有平台。每个平台的读者预期不同，**同一个内容必须有不同入口动作**。

| 渠道 | 读者 | 它给我什么 | 入口动作 | 发什么 |
|---|---|---|---|---|
| **GitHub** | 开发者 | Star、Issue、可信度背书 | 点 Star / 下载 | README（已改造） |
| **公众号**（晨曦AI研习） | 关注你的技术人 | **可反复触达的私域** | 关注 + 回复关键词 | 首发长文（`02`） |
| **掘金** | 前端/全栈 | 技术声誉、外链权重 | 跳 GitHub | 技术长文（`01`） |
| **知乎** | 搜索来的长尾 | 持续搜索流量 | 跳 GitHub | 回答式改写（`03` §5.1） |
| **V2EX** | 硬核开发者 | 真实反馈、口碑 | 直接下载 | 自曝缺点版（`03` §5.3） |
| **小红书** | 非技术但用 md 的人 | 意外增量 | 私信/评论 | 6 图短文案（`03` §5.4） |
| **即刻 / 朋友圈** | 熟人盘 | 第一批 star 与反馈 | 转发 | 短版（`03` §5.5） |
| **视频号 / B站** | 泛技术 | 认知渗透 | 简介导流 | 60 秒竖版（`03` §5.6） |
| **技术群** | 同行 | 精准首批用户 | 直接发 | 短版 + 一张图 |

**关键分配**：

- **GitHub 是"落地页"**，所有渠道最终都指向它 → 所以 README 首屏决定一切。
- **公众号是"蓄水池"**，唯一能二次、三次触达的渠道 → 所以关键词承接必须先配好。
- 掘金/知乎是"引流管"，不要指望在这里涨粉，只指望它们把人送到 GitHub 和公众号。

## 四、指标：三档判定，别只看绝对值

**基线假设**（无粉丝基础、无预算、单人运营）——这些是**假设，不是承诺**，用来判断"该不该继续投入"。

| 指标 | D0 | D7 | D30 | 怎么看 |
|---|---|---|---|---|
| GitHub Star | 15–40 | 80–150 | 200–400 | 唯一公开的信任指标 |
| Release 下载 | 20–50 | 150–300 | 600–1200 | 真正在用的人数 |
| 公众号新增关注 | 30–60 | 100–200 | 300–500 | 私域沉淀 |
| 关键词回复次数 | 10–30 | 60–120 | 200–400 | **最真实的转化率** |
| Issue / 反馈 | 1–3 | 5–10 | 10–25 | 有人用才会提 |

### 判停条件（比目标更重要）

| 现象 | 说明什么 | 该改什么 | 不要做什么 |
|---|---|---|---|
| **下载 < 50 且 star < 30**（D7） | 不是渠道问题，是**首屏问题** | 回去改 README 首屏：加 GIF、把截图提到第一屏、Star 引导放显眼处 | 别再发新渠道，浪费内容 |
| **star 少但下载多**（下载/star > 0.5） | 有人用，但不觉得值得背书 | 补「谁在用它」/ 典型场景 / 用户反馈；把 Star 引导写具体 | 不要开口求 star |
| **阅读高但关键词回复 < 2%** | 钩子没吸引力 | 改文末区块，把"回复能拿到什么"写成具体清单 | 不要换渠道 |
| **阅读低但回复率高**（> 8%） | 内容精准，但曝光不足 | 加大互推与转载授权；给垂直社群单独写版本 | 不要改标题风格 |
| **Issue 里 3 个以上同一问题** | 文档没写清楚 | 立刻补 FAQ，并在 README 对应位置加提示 | 不要一个个回，要写进文档 |

### Demo GIF 怎么录（20 秒，5 分钟能完成）

1. 用 Windows 自带 `Win + G`（Xbox Game Bar）或 OBS 录屏，只录应用窗口
2. 按这个顺序操作，**不要有鼠标乱晃**：
   - 双击一个大 md（3 秒）
   - 切「卡片」（2 秒）
   - 切「纸张」（2 秒）
   - 表格点表头排序（3 秒）
   - 点「图表」出柱状图（3 秒）
   - `Ctrl+R` 最近打开（3 秒）
   - 切深色主题（2 秒）
3. 转 GIF 并压到 5 MB 以内（GitHub 对 README 里的 GIF 没有硬限，但超过 10 MB 加载很慢）：

```bash
ffmpeg -i demo.mp4 -vf "fps=12,scale=960:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" -loop 0 demo.gif
```

4. 存为 `docs/screenshots/demo.gif`，README 里替换掉现有的 GIF 占位注释

> 一条硬要求：**GIF 必须放在 README 第一屏**（徽章下方、痛点表上方）。放第 84 行等于没放——手机端根本划不到。

## 八、最后一句

这份计划里最贵的不是渠道，是 **B1–B4 那四个雷**。

一个写错的"同名公众号"、一个没建的仓库、一个没配的关键词、一个没传的 Release——**任何一个都足以让前面所有内容白写**。

所以顺序是：先把桶补好，再倒水。
