# 公众号承接配置与多平台改写

> 配套 `02-公众号-首发长文.md` 使用。这份文件解决"文章发出去之后，人来了怎么接住"的问题。
> 核心原则：**用户在公众号里拿不到东西，就等于没来。**

---

## 一、为什么承接比发文更重要

公众号的流量结构是"漏斗极窄、全靠转发"：

```
一次转发 ──> 10 个人点开 ──> 3 个人读完 ──> 0.5 个人关注 ──> ?
```

最后那个问号就是承接。如果关注后回复「MDReader」收到的是"感谢关注"，那 0.5 个人下个月也会取关。

而承接是**一次性配置、长期生效**的。花 30 分钟配好，未来每一篇文章都在为你工作。

---

## 二、关键词自动回复（P0，发布前置条件）

### 2.1 必须配置的关键词

| 关键词 | 触发场景 | 回复内容 |
|---|---|---|
| `MDReader` | 产品内提示、文章末尾 | **主回复，见 2.2** |
| `MD` | 用户懒得打全 | 同 `MDReader` |
| `下载` | 模糊意图 | 同 `MDReader` |
| `源码` | 开发者 | GitHub 地址 + License 说明 |
| `技术分享` | 技术文末尾 | 技术长文链接 |

> 微信后台：自动回复 → 关键词回复 → 添加规则。**一个规则最多 5 个关键词**，所以 `MDReader`、`MD`、`下载` 可以合并成一条。

### 2.2 `MDReader` 主回复内容（直接抄）

```
MD Reader 是一个双击就开的本地 Markdown 阅读器：单文件、零联网、不用装依赖。

📦 下载（按需选一个）
· 便携版（推荐先用这个，解压即用）
  github.com/guizige-890323/mdreader/releases
· Windows 安装版（能把 .md 设成默认打开）
  同上，下载 Setup 结尾的那个
· iOS / iPadOS 版（加到主屏幕当 App 用）
  同上，下载 iOS-PWA 那个

🚀 30 秒上手
解压 → 双击「启动 MDReader.bat」→ 把 .md 拖进去

💻 源码（MIT，随便改）
github.com/guizige-890323/mdreader

❓ 遇到问题
仓库里有 Issue 模板，或者直接在这里回我，我会看。

—— 回复「技术分享」，看我写这个项目的四个工程决策
```

**为什么这么写**：

| 设计 | 原因 |
|---|---|
| 先给"推荐先用这个" | 三个包会让新手卡住，必须指定一个默认选项 |
| 不写"点击蓝色字体" | 公众号里不能放外链，只能给路径，别让用户找不存在的链接 |
| 末尾埋「技术分享」 | 把关注者往第二篇内容导，增加二次触达 |
| 给一条"直接回我" | 单人项目最大的优势是能对话，别浪费 |

### 2.3 被关注回复（新关注自动发的第一条）

```
来了 👋

我是桂子哥，一个在昆明做运维数字化的工程师。

这个号写两类东西：
① 我自己做的小工具（都是免费的，MD Reader 回复「MDReader」直接拿）
② 把工作中踩过的坑写清楚，省得你再踩一遍

最近在写的一个：一个 3.8 MB 的 HTML 文件，怎么扛住 1100 篇笔记的阅读 —— 回复「技术分享」看。

有想聊的随时回，我基本都会看。
```

**注意**：不要写"回复 1 领取资料包"这种编号式，用户记不住。用**有意义的词**（`MDReader`、`技术分享`），只在需要时才打。

## 三、菜单栏设计（三栏）

```
┌─────────────┬─────────────┬─────────────┐
│  拿工具      │  读技术      │  找我        │
├─────────────┼─────────────┼─────────────┤
│ MD Reader   │ 技术复盘     │ 关于我       │
│ 其他小工具   │ 踩坑记录     │ 联系 / 反馈  │
└─────────────┴─────────────┴─────────────┘
```

| 菜单项 | 类型 | 指向 |
|---|---|---|
| 拿工具 → MD Reader | 跳转网页 | GitHub Releases 页 |
| 拿工具 → 其他小工具 | 跳转网页 | 后续工具用同一个落地页，先留空 |
| 读技术 → 技术复盘 | 跳转图文 | 技术长文（发布后回填） |
| 读技术 → 踩坑记录 | 跳转图文 | 后续文章，先留空 |
| 找我 → 关于我 | 跳转图文 | 一段自我介绍 + 邮箱 |
| 找我 → 联系 / 反馈 | 跳转网页 | `mailto:527400412@qq.com` 或仓库 Issues |

**关键**：菜单里能放**外部链接**（只有已认证的服务号/订阅号的部分菜单支持，未认证号只能跳图文或小程序）。如果你的号不支持外链，全部改成"跳转图文"，图文里再用关键词引导——**不要留死链**。

## 四、文末钩子（三种，按文章类型选）

### A 型 · 产品文用（引导关注 + 回复）

```
如果这个工具帮你省了几次"为了看个 md 开 IDE"的时间，
去 GitHub 点个 Star 就够了 —— 那是我唯一会看的指标。

仓库：guizige-890323/mdreader
下载：本号回复「MDReader」，直接给你三个版本的地址。

有问题在仓库提 Issue，或者在这里回我，我都会看。
```

### B 型 · 技术文用（引导关注 + 下一篇）

```
这篇写的是"为什么我不重写 Mermaid"。
下一篇想写：一个 3.8 MB 的 HTML，怎么在 0.6 秒内打开 2000 行文档 —— 拆开讲渲染管线。

不想错过的，关注一下。回复「技术分享」拿这篇的完整版（含代码）。
```

### C 型 · 转发用（弱化引导，强化传播）

```
如果这篇让你想起某个总在群里发 .md 的同事，转给他。
他可能不需要看技术细节，只需要一个能双击打开的东西。

回复「MDReader」直接拿。
```

> 三种都不要用"不关注就无法领取""转发三个群截图领取"这类话术。2026 年平台对诱导关注/诱导分享检测很严，轻则限流，重则封功能。**改成"关注后持续更新 XX"这种价值回馈表述，合规且留存更高。**

## 五、多平台改写（一鱼多吃）

母体：`02-公众号-首发长文.md`（1800 字）。以下是同一内容的五个平台版本。

### 5.1 知乎回答版

**投放位置**：搜索"Markdown 阅读器 推荐""有什么好用的 markdown 软件""怎么优雅地看 md 文件"下高赞问题的回答区。

**结构**（不要整段搬公众号文章，知乎反感软文）：

```
先说我试过的方案和各自的坑：
· Typora —— 好用，但要装、要授权、打开是编辑态
· Obsidian —— 库的概念很好，但看单篇要开整个库
· VS Code 预览 —— 我得先有个工作区
· 在线编辑器 —— 内网文档过不去合规

我的需求很窄：双击一个 .md，看，关掉。

后来自己写了一个，单文件 HTML，3.8 MB，零联网。
[这里放 3 条具体差异，每条配一张图]
· 卡片皮肤按 ## 切块，2000 行手册变 8 张卡
· 表格点表头排序 + 一键柱状图
· Obsidian 的 [[双链]] 和 callout 能正常显示

开源了：github.com/guizige-890323/mdreader
（MIT，随便改；不喜欢的直接 fork）
```

**注意**：知乎回答里**必须真的回答问题**，工具放最后。纯广告会被踩到折叠。

### 5.2 掘金版

**标题**：《我做了个 3.8 MB 的单文件 Markdown 阅读器，聊聊里面的四个工程决策》

**与公众号版的差异**：
- 保留全部代码块（掘金读者要看代码）
- 开头加 `## 背景` 讲约束推导
- 结尾加 `## 技术栈` 列表：原生 JS / Python 标准库构建 / Electron / Mermaid
- 标签：`前端` `JavaScript` `开源` `Markdown` `Electron`

> 掘金版直接用 `01-技术分享-单文件与流程图引擎.md`，几乎不用改。这篇比产品文更适合掘金。

### 5.3 V2EX 版

**节点**：`/go/create`（分享创造）

**标题**：《[分享] 做了个本地 Markdown 阅读器，单文件 HTML，零联网》

**关键**：V2EX 用户对营销极度敏感，**必须自曝缺点**，否则会被嘲讽。

```
做这个的起因很无聊：同事发来个 2000 行的排查手册，我只想看第三节的表。

试过的方案：VS Code（等加载）、在线编辑器（内网资料不能出网）、系统预览（滚不完）。

所以做了个单文件 HTML 的阅读器，双击即开，零网络请求。
3.8 MB，其中 mermaid 占 3.2 MB —— 不想要流程图的话其实可以更小。

已知问题（先说，省得你们问）：
· 编辑只够改几行（按块编辑），写长文还是得用 Typora / Obsidian
· 只做了 Windows 安装包，macOS 的构建配置写好了但没在 Mac 上编过
· iOS 版是 PWA，不能注册 .md 默认关联（系统限制）

```

### 5.4 小红书版

**标题**：《我做了个双击就能看 md 的小工具（免费开源）》

**形式**：6 图 + 短文案（小红书不看长文）

## 六、搜一搜优化（长期免费流量）

公众号文章会被微信搜一搜收录，这是新号最被低估的流量口。

| 位置 | 要埋的词 | 现在怎么写 | 建议怎么写 |
|---|---|---|---|
| 标题 | `Markdown` `阅读器` `开源` | 《我把 2000 行排查手册…》—— **一个搜索词都没有** | 《不联网的 Markdown 阅读器开源了：双击 .md 就能看》 |
| 首段 100 字 | 同上 + `本地` `离线` | 场景描述 | 场景后在括号里补一句"（一个本地离线的 Markdown 阅读器）" |
| 摘要 | 4–5 个词 | 见首发稿 | 已含"Markdown 阅读器""开源""单文件" |
| 话题标签 | `#Markdown` `#开源` `#效率工具` | — | 发布时勾选 |

**取舍**：场景式标题点击率高但搜不到；关键词式标题搜得到但点击率低。

**建议**：首篇用场景式（建立人设、冲转发），**第二篇开始用关键词式**（吃搜索流量）。或者用主副标题：《双击 .md 就能看：一个不联网的 Markdown 阅读器开源了》——两个都要。

## 七、合规红线（四不做）

| 不做 | 原因 |
|---|---|
| 刷 Star / 买粉 / 刷阅读 | GitHub 会隐藏统计甚至封号；微信会降权，且假粉拉低完读率，反而减少推荐 |
| "不关注无法领取"式强制诱导 | 平台明令禁止，轻则限流重则封功能 |
| 互关日增量 > 现有粉丝 10% | 触发风控预警 |
| 在纯转发群刷链接 | 零转化，且容易被踢；正确姿势是先在群里输出价值，等人来问 |

## 八、效果怎么看（每周 10 分钟）

| 指标 | 在哪看 | 判读 |
|---|---|---|
| 新增关注 | 公众号后台 → 用户分析 | 发文日 vs 非发文日差值 = 单篇拉新 |
| 关键词回复次数 | 后台 → 消息分析 | **这是最真实的转化指标**：回复「MDReader」的人数 ≈ 真的想用的人数 |
| 图文完读率 | 后台 → 内容分析 | < 30% 说明开头太长或配图太靠后 |
| 分享次数 / 阅读 | 同上 | > 8% 说明内容有传播力 |
| GitHub Star 增速 | 仓库 Insights → Traffic | 与发文日对齐看，验证渠道贡献 |
| Release 下载量 | 仓库 Insights → Traffic | 下载/Star 比值 > 0.3 说明真有人用，不只是收藏 |

**如果 7 天后关键词回复数 < 阅读量的 2%**，说明钩子没吸引力 —— 不是渠道问题，是"回复了能拿到什么"没讲清楚。改文末区块，不要换渠道。
