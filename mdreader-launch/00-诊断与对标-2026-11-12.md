### 8.1 仓库源码落后发布包约 1.5 小时（已修，提交 `a48fec3`）

比对仓库与工作区同名文件时发现：

| 文件 | 仓库（00:47 快照） | 工作区（02:31） | 结论 |
|---|---|---|---|
| `MDReader/src/template.html` | 96,281 B | 97,977 B | 仓库落后 |
| `MDReader/src/app.js` | 90,751 B | 93,053 B | 仓库落后 |
| `MDReader/dist/MDReader.html` | 3,959,187 B | 3,963,165 B | 仓库落后 |

而发布包的生成时间是 02:33——**用的是新源码**。后果很直接：任何人 clone 仓库后构建出来的程序，与你上传的包行为不一致（缺专注阅读、还带着已移除的 crumb 面包屑）。

更隐蔽的是：即使源码同步了，`dist` 没重建，`git status` 依然是干净的——**"干净"只说明两者一致，不说明它们是对的**。这正是我在 P0 阶段加的漂移检查能抓、但必须有人先跑一次才能发现的问题。

修复后验证：仓库内 `build.py` 重建产物 md5 `ad4bd5b4…`，与工作区 `dist` 及便携版包内 HTML **逐字节一致**。

> 教训：**发布前必须做一次"包内产物 ↔ 仓库源码"的对齐校验**，不能只看 `git status`。这条已写进 `04-发行推广计划.md` 的阶段 0 验收。

### 8.2 我自己把产品写成了"不能编辑"（已修，提交 `18cec42`）

写 FAQ 时我依据"阅读器"这个定位，直接写了"不能编辑，这是设计选择"。核对源码发现是错的：

- `template.html` 有 `btnEdit`（`Ctrl+E`）与 `btnSave`（`Ctrl+S`）
- `app.js` 有按块编辑：把文档切成标题 / 段落 / 列表 / 表格 / 代码 / 引用 / 分隔线，逐块修改，保留块间空行与 frontmatter
- `preload.js` 白名单里有 `writeFile(p, text, enc)`，桌面版原子写回原文件，支持 GB18030
- `CHANGELOG` v1.3.0 还列了三格式导出（HTML / PDF / Word）

一条错的定位描述，会让 FAQ、对比表、README 中英双版、公众号稿同时失真——**而且这种错不会被任何自动化检查发现**，因为文档内部自洽。

已改为准确表述：**能编辑，但只做到"够改一行"**（无语法高亮编辑、无多光标、无插件、无 Vim 模式），不是主力写作工具。

> 教训：写"我们不做 X"之前，先去代码里搜一遍 X 有没有实现。**产品文档里最危险的不是夸张，是把自己说小了。**
