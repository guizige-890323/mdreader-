## 二、明早 7:50（发布前 10 分钟）

### 2.1 建 GitHub 仓库

1. 打开 https://github.com/new
2. Repository name 填 **`mdreader`**
3. 选 **Public**
4. **不要**勾 "Add a README file"、**不要**选 .gitignore、**不要**选 license（仓库里已经有了，勾了会冲突）
5. 点 Create repository

### 2.2 推送（把下面三行粘进 Git Bash）

```bash
cd "/f/豆包工作空间/github开源项目/MD Reader"
git remote add origin git@github.com:guizige-890323/mdreader.git
git push -u origin main
git push -f origin v1.3.0        # -f 是保险：万一你之前推过旧 tag
```

**通过判据**：刷新页面能看到文件列表，右侧出现 `v1.3.0` 的 Releases 区块。

> 若 `git remote add` 报 `already exists`，改用：
> `git remote set-url origin git@github.com:guizige-890323/mdreader.git`
>
> 推上去后 GitHub 会自动跑 CI（约 3–5 分钟）。**这一步我已经在本机用干净副本完整模拟过一遍**：JS 语法、构建、同步、单文件断言、便携版打包、生成物漂移检测全过，便携版回归 17/17、主题矩阵 11/11。正常情况下应该是绿勾。万一红了，把红的那一步名字发我，别自己改。

### 2.3 建 Release

1. 仓库页右侧 → **Releases** → **Draft a new release**
2. Choose a tag → 选 **`v1.3.0`**（已存在的那个，不要新建）
3. Release title 填：`MD Reader v1.3.0`
4. 描述区：把 `05-Release-Notes-v1.3.0.md` 的**全文**粘进去
5. 上传附件，**按这个顺序**（第一个会排在最上面，就是用户默认看到的）：

| 顺序 | 文件 |
| --- | --- |
| 1 | `MDReader-便携版-v1.3.0.zip` |
| 2 | `MD Reader Setup 1.3.0.exe` |
| 3 | `MDReader-Win免安装-v1.3.0.zip` |
| 4 | `MDReader-iOS-PWA-v1.3.0.zip` |

6. **不要**勾 "Set as a pre-release"
7. 点 **Publish release**

**通过判据**：换一台设备或开无痕窗口，打开 `github.com/guizige-890323/mdreader/releases`，4 个附件都能看到下载按钮，README 顶部的 Release / Downloads 徽章不再是灰色。

## 三、明早 8:20（发公众号前）

### 3.1 配关键词（不配就别发文）

公众号后台 → 自动回复 → 关键词回复 → 添加规则：

| 关键词（一条规则里填 4 个） | 回复内容 |
| --- | --- |
| `MDReader`、`MD`、`下载`、`md` | 见 `03` 文件 §2.2 的那段文案 |

同时配「被关注回复」，见 `03` §2.3。

**通过判据**：用你自己的另一个微信号回复 `MDReader`，能收到完整下载指引。

### 3.2 发文

1. 标题用：**《我把 2000 行排查手册，做成了一个双击就开的窗口》**（与 `02` 稿件的推荐标题逐字一致，不要改写）
2. 摘要填：`开源一个本地 Markdown 阅读器：单文件 HTML、零联网、双击即开。支持卡片/纸张双皮肤、表格排序出图、Obsidian 双链与 Mermaid 流程图。附 Windows 安装版与 iOS 主屏幕版。`
   —— 公众号没有"副标题"，搜索关键词只能靠摘要和标题吃，所以摘要别省
3. 封面：主图用 `assets/cover-dark-900x383.png`，分享缩略图用 `assets/thumb-dark-200x200.png`
4. 正文：`02-公众号-首发长文.md`，把 6 处 `〔配图…〕` 换成真实截图
5. 话题标签：`#Markdown` `#开源` `#效率工具`
6. 点「原文链接」→ 填 `https://github.com/guizige-890323/mdreader`（**这是正文里唯一能点的地方，别浪费**）
7. 发布

> 正文里出现 `github.com/guizige-890323/mdreader` 的地方只是**文字**，用户点不了。所以「原文链接」和关键词回复两个入口必须都配好。
