# 发布说明 · 时间线与检查表

> 一次发布拆成 6 个动作、跨 4 天。**不要同一天全平台铺开**——四个平台的推荐池互相不重叠，
> 但同一天发会让你无法判断哪条素材有效，也容易被判定为营销号。

---

## 一、时间线

| 时间 | 平台 | 动作 | 目的 |
| --- | --- | --- | --- |
| **T-0（今晚）** | GitHub | 建空仓 → push `main` + `v1.7.0` | 先有可验证的源头，别人问「代码呢」时有得给 |
| **D0 20:00** | 公众号 | 发《我把一个 4.6 MB 的文件，做成了一个 Markdown 阅读器》 | 主阵地，长文承载「为什么」 |
| **D0 20:10** | 朋友圈 | 第 1 条 | 承接公众号，给熟人一个点开理由 |
| **D0 21:00** | GitHub | 建一个 **空 Release**（只写描述、不传附件） | 仓库页有版本记录，但没有会让人扑空的下载按钮 |
| **D+1 12:30** | 视频号 | 45 秒录屏 | 午休刷手机时段，视频比文字更适合展示「快」 |
| **D+1 20:30** | 朋友圈 | 第 2 条（架构图对比） | 给昨天没点开的人第二次机会 |
| **D+2 19:30** | 抖音 | 15 秒版先发，2 小时后看数据再决定是否发 35 秒版 | 抖音是唯一需要「投喂测试」的平台 |
| **D+3** | GitHub | **开放下载**：编辑 Release，补传 5 个附件 | 让仓库裸跑 3 天，有问题先修，再给人装 |
| **D+3 20:30** | 朋友圈 | 第 3 条（为什么不加云同步） | 用价值观收尾，把「小」讲成主动选择 |

## 二、四平台适配差异（同一份内容，四种写法）

| 维度 | 公众号 | 朋友圈 | 视频号 | 抖音 |
| --- | --- | --- | --- | --- |
| 标题长度 | 30 字内 | 无标题 | 20 字内 | **≤30 字**，带 1 个话题 |
| 首屏要求 | 前 3 行抓人 | 前 2 行（折叠线以上） | 前 1.5 秒 | 前 1.5 秒，更狠 |
| 内容形态 | 1500–2000 字 + 4 图 | 80–120 字 + 1–3 图 | 45 秒录屏 + 大字幕 | 15 秒 / 35 秒，可口播 |
| 语气 | 第一人称、讲动机 | 像跟朋友说话 | 事实 + 反差 | 结论先行，不客套 |
| 链接 | 可放阅读原文 | **不放**（降权） | 简介里放关键词 | 评论区置顶 |
| 禁忌 | 不要「重磅」「震惊」 | 不要连发三条 | 不要 logo 开场 | 不要念参数 |
| 转化动作 | 星标 + 关键词 | 私聊问细节 | 进合集 | 置顶评论 |

## 四、发布前 10 分钟检查表

```
□ GitHub 仓库可访问，main 分支 199 个文件，tag v1.7.0 存在
□ Release 是「只有描述、没有附件」的状态
□ 公众号关键词已配置，小号实测能收到回复
□ 公众号封面比例正确（900×383，不要用 2.35:1 的横图）
□ 正文里的 4 张图已上传到公众号素材库（不要外链）
□ 视频号 / 抖音封面是大字版，缩到 200px 宽仍可读
□ 录屏里没有你的私人文件、通知弹窗、浏览器其他标签
□ 评论区/置顶评论已准备好（GitHub 搜索词 + 下载状态说明）
□ 三个标题已选定一个，不要在发布时再犹豫
□ 手机上看一遍自己的文章（80% 读者在手机上看）
```

## 五、发布后 24 小时要做的事

| 时间 | 动作 | 为什么 |
| --- | --- | --- |
| +1h | 看公众号「阅读→在看」比，低于 3% 说明标题可以但内容没打动人 | 决定要不要改标题重发（只能改一次） |
| +3h | 回所有评论，尤其「能不能支持 X」 | 早期评论决定算法是否继续推 |
| +12h | 看 GitHub star 曲线，若 0 star 说明公众号没转化 | 检查文末引导是否太弱 |
| +24h | 记录四个平台的数据（阅读/播放/完播/涨粉） | D+3 开下载时，用数据决定主推哪个平台 |

---

## 六、如果只能做一件事

**先让 GitHub 仓库活着，再谈其他平台。**

一个没有代码的空口宣传，来的人点进去看到 404，会直接关掉，而且不会再来第二次。仓库在、代码能跑、README 能看懂——这三件事做到了，哪怕一条视频都没发，也会有人自己找过来。
