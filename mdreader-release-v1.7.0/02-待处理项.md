### 2. 首发前暴露并修掉的两个 CI 问题

| # | 问题 | 症状 | 修法 |
| --- | --- | --- | --- |
| 1 | **Windows runner 的 stdout 是 cp1252** | 构建步骤直接 `exit 1`，日志 `UnicodeEncodeError: 'charmap' codec can't encode ... dist/示例文档.md`。本机 Git Bash 是 UTF-8，**本地永远复现不出来** | 五个构建脚本入口加 `stdout.reconfigure(encoding="utf-8")`；`ci.yml` 顶层加 `PYTHONUTF8=1` |
| 2 | **GitHub Actions 的 bash 默认 `-eo pipefail`** | 漂移检查「静默失败」：只剩一句 `Process completed with exit code 1`，summary / 评论 / `::error::` 全都没有。真因是 `n=$(git diff --no-index …)` 在有差异时返回 **1**，赋值语句带崩 errexit；诊断代码里的 `git diff \| head` 还会因 SIGPIPE 返回 141 | 该 step 加 `set +e` / `set +o pipefail`；`no-index` 那行补 `\|\| true`；三个失败分支保留显式 `exit 1`，真漂移仍会红 |
| 3 | **Dependabot 开了 8 个升级 PR** | 仓库首页挂一排红色 CI；electron 45.3.0→45.3.2 会牵动安装包 | 配置已改为 monthly + 分组（`electron-stack` / `actions`），忽略 electron 大版本；**8 个 PR 全部已关闭、bot 分支已删** ✅ |

> 第 2 条值得记下来：它让「查日志」这件事本身失效——`-e` 下任何中间命令返回非零都会静默中断，
> 所以要么拿不到诊断，要么拿到的是假绿。以后在 Actions 里写诊断代码，第一行就该 `set +e`。

## 四、明确不做（写进 README，避免反复被问）

| 提议 | 决定 | 理由 |
| --- | --- | --- |
| 账号体系 / 云同步 | ❌ | 一旦有了账号，就要处理隐私、合规、服务器成本，产品性质就变了 |
| AI 摘要 / AI 问答 | ❌ | 会引入网络请求，破坏「零联网」这个唯一硬承诺 |
| 数学公式（KaTeX） | ❌ 暂不 | 会让单文件再涨 1 MB+，且与「排查手册」主场景不重叠 |
| 插件市场 | ❌ | 插件意味着执行第三方代码，和「单文件可审计」直接冲突 |
| 移动端原生 App | ❌ 暂不 | 需要 SwiftUI 重写一遍，投入产出不匹配 |

> 这些不是永久拒绝，是「当前阶段不做」。README 的「和同类工具比」一节已经写明各自的替代方案，读者不会觉得被敷衍。
